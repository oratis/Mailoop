## 复现实验

运行 npm ci、npm run build 和 npm test。集成测试启动临时 PostgreSQL，使用合成活动与联系人。浏览器检查依赖 Playwright Chromium。邮件协议检查依赖 Java 17+、keytool 和 curl，首次运行会取得按 SHA-256 固定的 GreenMail 测试服务。所有测试账户均属于临时回环服务。 [GreenMail](https://greenmail-mail-test.github.io/greenmail/)

```sh
npx playwright install chromium
node --import tsx scripts/browser-check.ts
bash scripts/check-mail.sh
node --import tsx scripts/capacity.ts
```

- **产品走查**。12 行研究结果含 2 行重复和 2 行缺少联系证据。由两名成员的模拟邮箱处理 6 个获许可的收件人。一次回包丢失的快照显示 5 次已受理、1 次待对账，真人回复 2/5、兴趣 1/5、硬退信 1/5、退订 1/5。后续重复事件保持分母稳定。
- **模型和搜索**。OpenAI、Anthropic 和 Gemini 分别用同一公开合成目录完成取证和导入预演，每次生成有界消耗一次模型请求。每家都至少一次产出 2 位候选、1 条可回查的商务邮箱和 1 个联系点缺失原因。研究过程中也观察到模型返回不合规范的结果，任务可保留检查点并显示错误。实际搜索服务返回三条公开来源，三条均可独立读取。这组样本衡量接口与证据一致性。
- **协议收发**。两个合成邮箱通过 TLS、SMTP 鉴权和 IMAP 登录。发件端提交带 Message-ID、List-Unsubscribe 和 List-Unsubscribe-Post 的 MIME，在接收端检查邮件头，再主动回一封并按原线程关联。另以真实飞书 SMTP/IMAP 账户做过连接和认证。
- **容量**。单机开发环境上，5 个活动、20 个模拟邮箱、1,000 位候选和 200 条预置受理记录，8 路并发调用签名入站处理函数。30,000 次调用包含 10,000 个不同事件和 20,000 次重复。样本耗时 9.33 秒、入站处理 P95 4 毫秒、5 份报告合计 671 毫秒、失败 0，数据库约 20.6 MB。此项测量覆盖签名验证、事务、幂等和报表查询；云服务网络、真实投递额度和长时间稳态运行另行测量。CI 会打印当前运行值。

## 运行边界

工作台支持手工认领、按规则分类和按活动收件。Gmail 与 Graph 的增量通知用于唤醒相关线程，实际同步水位在成功读取后推进。游标过期会清除对应的状态并重扫关联会话。飞书以时间窗和页码轮询，IMAP 以 RFC 引用搜索，已发箱不能证实受理时保留 unknown。回退到上一版本前需要保留后来发生的退订和撤权事实。

研究预算以外部请求次数实施硬限制。为绑定提供 rates（currency、input 和 output，后两项均为每百万 tokens 的价格）后，按服务商返回用量计算模型费用估算；有缓存分级或缺价格的请求单列。人工、订阅和外部成本可通过带币种的业务事件录入。一次可用性联调、一次协议回放和市场试点代表不同的验收层级。 [部署与提供商矩阵](self-host.md) · [市场试点设计](../research/market.md)
