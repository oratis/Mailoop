# 开发计划、试点与发布验收

当前版本为设计基线。以下安排以两名全栈工程师和一位兼职运营/QA 为估算前提。M0–M3 共约 8 周，外部 OAuth 审核、测试租户授权与真实账户资格单独跟踪。周数为排期假设，发布依据为验收结果。

| 阶段与依赖 | 工程交付 | 由谁验收，如何判定完成 |
| --- | --- | --- |
| M0 · 第 1 周 | 仓库骨架、Postgres 迁移、workspace 身份、角色、任务租约与事件流。模拟模型、可确定重放的搜索源和测试邮箱；Compose 启动方式 | 工程 A 负责 API/数据，B 负责 worker/接口。全新实例建两组织，CLI 和极简 Console 均能读到自己的活动，跨组织引用拒绝。模拟一封从草稿到收信回放 |
| M1 · 第 2–3 周，依赖 M0 | 研究、去重与证据 UI、预演及幂等应用；首个真实模型与授权搜索连接，另两家在 M3 前完成。可在 Claude Code/Gemini CLI 中使用的研究说明及导入示例 | 工程 A 负责 schema/研究，B 负责 Console/模型，运营盲核。合成样例产生一条待核合作地址及一条缺失原因；重复应用返回原结果，注入“已同意”的产物被拒 |
| M2 · 第 4–5 周，依赖 M1 | 品牌事实、首封/回复/跟进草稿、审批、抑制、一键退订、事务投递、飞书授权/草稿/投递/回信/对账、组织及身份额度 | 运营用测试租户和自有收件箱走完单提供商闭环。双击批准、并发撤权、429、提交中崩溃、临时/硬退信、退订和回复停止后续任务均通过 |
| M3 · 第 6–8 周，依赖 M2 | Gmail 实现、双成员双提供商排程、三家模型 BYOK、收件箱和热池、日报和漏斗、备份恢复、自托管说明；符合资格的本地 ChatGPT 计划绑定预览 | 运营执行产品走查并从 2/5 下钻到两条真人回信。用两名成员和两个独立邮箱服务商测试实收实回。API key、订阅、无资格、撤权和预算不足分别显示正确状态 |
| M4 · 试点后按需求取舍 | Microsoft Graph、SMTP+IMAP、托管 connector；内容/转化回传和成本归因，扩展 skill/connector 发布接口 | 按 connector 契约逐个取得测试邮箱证据，再加入支持矩阵。业务回调重复、乱序、跨币种或归属不明时，报表有可解释结果 |

## 第一批可认领任务

| 顺序 | 交付物 | 验收样例 |
| --- | --- | --- |
| 1 | workspace、成员/活动权限与测试种子 | 两个组织可各自创建同名活动，跨组织取资源返回 404 |
| 2 | 把研究输入定义纳入校验与有界取证 | 合成 JSON 通过；无证据的公开地址、带发送许可的研究结果被拒；缺联系人必须给原因 |
| 3 | run、step、event 和 CLI 事件订阅 | 读到第 N 条事件断开，重连后从 N+1 恢复；已完成的研究步骤不再计费 |
| 4 | FakeMailbox、审批和 dispatch 租约 | 模拟受理后断网，只出现一个上游消息；重启后由对账结束 unknown |
| 5 | 可执行的竖向切片 | 浏览器中由 brief 走到回复，从报告追溯审批者、发件身份与来源 |

任务 1 为租户边界的前置；2、3 和模拟 adapter 可独立开发，4 的集成依赖 1 和 3，5 汇总全部。此后才将真实 provider 接到同一契约。

## 测试矩阵

| 层次 | 固定场景 | 放行证据 |
| --- | --- | --- |
| 域模型与契约 | 同人多渠道、共享经纪邮箱、跨活动冷却、缺失来源、证据过期、修改署名后审批失效、无分母指标 | 合成输入与预期行级结果匹配，来源、资格与审批三种权限独立 |
| 故障与并发 | 双 worker 争最后一个额度、租约过期、provider 接受后进程退出、一键退订与发送竞争、重复/乱序 webhook | 队列最终一致、无重复逻辑投递、预留有去向；已提交而无法取消的对账项可见 |
| 身份与隐私 | OAuth 回放/错误 workspace、撤权重联、成员离职、私信进入通知、研究网页内嵌指令、模型被禁读邮件 | 权限与 tenant 均正确；日志无地址、正文或密钥；模型只有获准上下文 |
| Connector 合同 | 发送/只草稿/无读取权限、别名、续期、未知回执、断游标全量补救、退订头存留 | 同一套测例在模拟及各适配器上按能力声明运行；实邮用专用账号和自有测试收件人 |
| 模型与研究评估 | 三家模型对同一多语 brief 提取硬条件，引用真实存在于合成页面的作品/联系方式；模型拒绝、异常 JSON、无搜索授权 | 对格式、引用、未知字段和重试有自动断言，合格候选的主观相关性另由运营盲核 |
| 端到端与报表 | 12 人走查、双邮箱、暂停与恢复、日报按时区分桶、重复回信、迟到回执 | CLI 和 Console 指向同一事件；从头重建后的聚合与明细相同；拟定 95% 的已入库事件在 5 分钟内可见 |

## 运行成本与容量试验

自托管试点假设每组织 20 个邮箱、5 个并行活动、每天 1,000 条候选。以假数据测试每小时 1 万条同步通知和 2 倍重复回调，给出队列等待、同步延迟、失败率、数据库占用和报告刷新时间。该数值是压测负载，真实发送上限取组织、成员与厂商中最小的允许值。

活动预估分四栏：模型输入/输出、搜索请求、数据商解锁、运维。可计价项按调用当时的费率和币种记录，已知总成本除以符合条件的唯一候选或已达成合作数。订阅用量、价格未知项和人工审核分钟单列。超预算时保存进度，允许缩小候选数或显式加预算。不同币种或缺失计费记录时不自动拼出总金额。

## 发布清单与回滚

1. 依计划先发布可离线运行的模拟活动，再发布限定测试租户的适配器。文档标明每个 connector/model binding 的支持等级、需要的 scopes、哪些测试已实测、哪些需组织管理员批准。Gmail 应用验证与模型计划资格在 M0 即开始核实；尚未通过的适配器或授权模式保持预览。
2. 新部署检查迁移版本、回调域名、数据库恢复、加密密钥和 OAuth 配置；对获准的自有测试地址进行双向试投，演练重联与退订。将地区、活动类型、提供商要求转成组织可配置的发送策略，试点前逐项确认。美国商业邮件及英国不同类型商业收件人的要求可分别查监管方指引。 [FTC](https://www.ftc.gov/business-guidance/resources/can-spam-act-compliance-guide-business) · [ICO](https://ico.org.uk/for-organisations/direct-marketing-and-privacy-and-electronic-communications/business-to-business-marketing/)
3. 试点先开放研究和草稿，再对选定组织开启单邮箱实发，最后启用双提供商。逐阶段核对未知回执、退信、抑制、回复归属和同步延迟。遇到重复投递、越权读写或退订失效，立即停发并保留入站与退订处理。
4. 回滚时停领新增外发，保留已提交请求的对账和队列状态，退回兼容应用版本。恢复备份要先补齐备份点后的抑制、撤权和已交付事实，再解封队列。不能证明历史状态完整的实例继续只读或草稿模式。
5. 首个公开运行版本应包含可复制的安装步骤、模拟活动、配置与升级文档、已知限制、发布标记和 MIT 许可。维护者按试点比较结果决定下一批 connector；以证据覆盖、回复归属、正常复用和审核耗时作为产品验证标准。 [市场试点指标](../research/market.md)
