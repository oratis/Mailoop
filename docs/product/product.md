# 产品方案

## 目标用户与核心承诺

Mailoop 帮创作者合作团队把一句「想找什么样的人」变成一批可复核的联系人，再用团队成员自己的邮箱开展合作。活动负责人能随时回答三件事：为什么选这位创作者、谁有权用哪个邮箱联系、对方回复后谁负责下一步。一个 workspace 对应一个组织，一个 campaign 对应一次目的明确的活动。

| 角色 | 常用动作 | 权限边界 |
| --- | --- | --- |
| 组织管理员 | 邀请与移除成员，设置发件域、地区策略、模型和预算 | 可停发和撤销组织访问；从成员邮箱发信另需该成员授予委托 |
| 邮箱所有者 | OAuth 接入自己的账号，核验 From，选择活动范围和限额 | 随时收回委托；接入时选择是否同步相关会话 |
| 活动运营 | 写 brief、选受众、预演导入、起草、领取回复 | 仅操作分配的活动和已委托的身份 |
| 审核人 | 复核证据、发送依据、文案、收件人和最终发件人 | 仅可审批明确授予的活动；批审能展开为逐行差异 |
| 分析员 | 按活动、成员、邮箱、市场查看漏斗 | 默认获得聚合数字；查看邮件正文需要额外的活动角色 |

小团队允许一人兼任运营和审核人，批准仍记录实名。成员可分别授予“创建草稿”“使用指定身份发送”“同步关联回信”。组织可要求不同人起草和审批；撤销任一相关授权会冻结依赖该授权的任务。

## 一次活动的验收走查

1. **建活动。** 运营输入“日语创作者，近 90 天发布过手冲咖啡教程，优先有商务合作入口”，填写产品事实、截止日、预算、发送地区和允许的来源。Agent 展示可编辑的检索条件、预计搜索页数和模型预算。
2. **找人。** Skill 用搜索连接器定位作品、频道和合作页面，记录采集时间和匹配理由。没有邮箱时保留候选及原因。运营可更改条件重跑，看到本次新增和已有候选。
3. **筛选。** 一组演示数据含 12 名候选：2 名重复，2 名没有可验证联系点，2 名只有公开地址、仍待补发送依据，6 名已有可核验的合作邀约许可。预演公布每行决定；应用只写入确认版本。运营能导出脱敏清单交接。
4. **写信。** 用近期作品写开场，使用活动批准的产品事实、署名及语言。审核页并排展示作品证据、来源、合作许可、主题和正文。合成器生成草稿后，确定性规则检查必需字段、有效期、链接和退订方式。
5. **发出。** 两位成员从飞书和 Gmail 各授权一个身份，分别承接 3 名获准收件人。审核人能看到每一行的实际发件身份、发送时间和后续步骤。投递前工作人员可以暂停活动，成员也可以撤回授权。
6. **接回。** 在示例观察时点，5 封已受理，1 封处于对账中。已受理的 5 封产生 2 个真人回复、1 封硬退信、1 次通过退订链接的退出。两条真人回信分配给会话负责人，其中 1 条表示愿意合作。每种结果都能在活动详情找到对应记录。 [指标演算](console.md)
7. **复盘。** 运营将确认达成的合作标记为 won，附外部引用。负责人可以区分候选质量、文案吸引力、邮箱故障和团队跟进延迟，并据此改下一版 brief。

## 决定能否发送的产品语义

- **来源**说明如何找到地址；**用途**说明地址面向哪种合作；**发送依据**记录谁在何时就哪个目的明确同意、请求过联系或具备经组织审核的适用依据。通过地址格式或供应商验证只更新可投递性。
- 申请人、已有合作方和首次发现的候选使用不同策略。运营给出目标国家、活动目的、组织联系信息和可证明的依据。适用地区、提供商或组织策略中任一项要求同意，即检查相符的同意记录。Gmail 首版商业活动只接受有可核验同意的收件人。 [Google Workspace 数据政策](https://developers.google.com/workspace/workspace-api-user-data-developer-policy)
- 退订、明确要求停止或地址永久退信立即写入组织级抑制。地址以组织范围的键匹配所有活动和邮箱，确认的整人拒联也覆盖已归并的联系点。临时拒绝某项合作可只结束本次关系。
- 首封发送时绑定邮箱和活动负责人。回复、跟进继承该线程。成员离职或凭据撤销时暂停，管理员可移交负责人；要换发件身份，需要新的有效委托和可见的新批准。

## 首版成功条件

在全新自托管实例中，运营可以不写代码完成上述走查。中断研究、重复导入、重复 webhook 和 worker 重启都能恢复。团队能回答每个阻塞原因和下一步，且可以从报表定位到受影响的记录。试点比较合格候选数、复核用时、有效回复和合作结果；运行可靠性与发布条件见[开发计划](../engineering/delivery.md)。
