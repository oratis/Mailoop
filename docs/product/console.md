# Console 与指标口径

## 页面和责任人

运营登录先看「今天需要我处理什么」。每个数字链接到同一 workspace、时区、活动和筛选条件下的明细。成员只能看到其活动和会话，分析员看到获准的聚合视图。

| 页面 | 主要内容 | 动作与反馈 |
| --- | --- | --- |
| 总览 | 待批准、超过 24 小时未处理回复、对账中、需重联邮箱、即将过期的品牌事实；今日已用及预留额度 | 点击即进入对应队列。区分“当前无待办”“没有权限”和“同步滞后” |
| 活动与 Brief | 活动目的、地区、受众、事实版本、预算、发送窗口、漏斗 | 预览一次活动的变动；暂停后列出已受理和仍可取消的条目 |
| 研究任务与导入 | 运行进度、消耗、逐项匹配理由、证据来源、采集时间、重复/待核/缺失原因 | 调整检索条件、抽检证据、预演差异、应用确定的版本、从断点继续 |
| 创作者档案与关系池 | 渠道、作品、经纪联系点、当前负责人、历史活动、拒联状态 | 合并待核重复项、补联系依据、把有意向的回复加入热池；共同经纪邮箱保留多位创作者的关系 |
| 发件箱 | 原稿与改稿、引用事实、实际收件人和 From、审批摘要、发送时间、投递结果 | 修改、逐封/逐批批准、取消、查看退回原因。发送结果未知时只提供对账动作 |
| 收件箱 | 我的/团队的已关联会话、待人工匹配、报价/有兴趣/问题/婉拒/自动回复/退订/退信 | 认领、纠正分类、标记已处理、原线程起草。无关私信默认不可见；模糊匹配仅邮箱所有者可核对线索 |
| 成员与连接 | 每个邮箱的所有者、已委托活动、权限、预算及使用量、同步延迟、最后成功时间 | 测试身份、降级为草稿、重联或撤权；模型密钥仅显示所属人、用途和授权状态 |
| 报告与活动流 | 活动/邮箱/负责人/模板版本/地区筛选，日报包含待办、漏斗和数据水位 | 查看明细或脱敏导出；迟到事件按发生日校正，显示最后重算时间 |

## 指标字典

按 workspace 时区显示日期，原始时间为 UTC。运营日报按事件发生日计数。效果报表按活动**首次受理日队列**计数，默认展示首封受理后 14 天内的结果；不足 14 天标注「观察中」。一个活动的一名创作者对应一条 engagement。重复 webhook 及同一线程的第二次回信不增加去重人数。

| 指标 | 分子及分母 / 计算方式 | 解释 |
| --- | --- | --- |
| 入围率 | 运营确认符合 brief 的唯一候选 / 去重后评估过的唯一候选 | 与找到邮箱的比例分开 |
| 可联系比例 | 具有效联系证据与当前发送依据、通过抑制检查的候选 / 活动入围候选 | 展示来源、地区或策略阻塞的数量 |
| 已受理 / 对账中 | 带 provider 受理证据的唯一 dispatch 数 / 另列结果未知 dispatch 数 | 受理是提交给邮箱服务商。仅有独立送达回执时才展示“确认送达” |
| 真人回复率 | 有真人回信的 engagement / 有首封受理的 engagement | 排除自动回复和系统退信；真人回复中明确拒联也计为真人，同时单列负向结果 |
| 有效意向率 | 有兴趣、询价或运营确认有实质合作意向的 engagement / 有首封受理的 engagement | 保留分类版本、人工订正和原始消息引用 |
| 硬退信率 | 已确认硬退信的 dispatch / 已受理 dispatch，按同一投递队列 | 临时退信另列；结果未知先单列，对账后再入分母 |
| 退订率 | 队列中有退订的唯一收件地址 / 已受理的唯一收件地址 | 同一地址的链接退订和人工拒联合并计一次，保留两个事件 |
| 合作转化率 / 单次合作成本 | 标记 won 的 engagement / 有首封受理的 engagement；同币种已知可归属成本 / won 数 | 标明成本覆盖范围、币种、归因窗口；订阅计划成本未知则单列，无分母显示空值 |
| 回复处理时间 | 首条需处理来信到首次人工处理的时长，报 P50/P90 | 待办同时显示尚未处理的最长等待时间 |

**演算。** 产品走查时点有 6 条投递、5 条已受理、1 条结果未知，5 个已受理地址分别属于 5 位创作者。真人回复率为 2/5，有效意向率为 1/5，硬退信率和链接退订率各为 1/5。对账若确认第 6 封已被受理且没有后续事件，真人回复率会重算为 2/6。演示数据和试点目标均不代表实测结果。 [活动走查](product.md)

首版默认关闭打开像素和点击改写。产品评估以回复和明确合作结果为主。后续业务回调须携带来源、外部事件 ID、金额与币种（如适用）；同一转化按组织和来源去重，在多个可能活动之间按配置的归因规则分配。
